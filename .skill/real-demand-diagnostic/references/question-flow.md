# 分阶段追问与现场观察

## 追问规则

- 先复用已有事实，不要求重复描述。
- 每次只问一个最能改变结论的问题。
- 询问“最近一次发生了什么”，少问“会不会”“愿不愿意”。
- 要求动作、次数、时长、金额、后果和原话。
- 不提示理想答案，不替受访者解释动机。
- 每轮更新“事实／推断／未知”三栏。

## 起始问题

材料几乎为空时，只问：

> 请讲一个最近真实发生的例子：谁在什么时刻遇到了什么问题，当时具体怎么处理？

只有产品介绍、没有用户事件时，问：

> 最近一个可能使用它的真实人物是谁？上一次问题发生时，他没有这个产品，是怎么把事情做完的？

## 想法期

按缺口逐个追问：

1. 最近一次问题发生在什么时候？触发事件是什么？
2. 当事人原本想把什么事情推进过去？不解决会发生什么？
3. 他用了哪些工具、人或手工步骤凑合？
4. 这套绕路花了多少时间、钱或精力？有没有因此放弃？
5. 同一个人发生过几次？还见过哪些人出现相同场景？
6. 能否先人工交付最小结果，并要求资料、预约、迁移或定金？

想法期结束条件：写出需求候选与最小承诺实验。不得宣布产品已经解决需求。

## 原型期

优先追问：

1. 有没有让真实用户在不讲解、不代操作的情况下完成关键任务？
2. 卡住、回退、绕开或误用发生在哪一步？
3. 使用前后的目标结果有什么变化？有没有基线？
4. 用户为什么没有继续用原来的办法？原办法在哪些条件下仍然更好？
5. 下一次相同问题出现时，他是否主动回来？

演示、问卷和“用户说很好”只能保留为 E0。

## 使用期

优先追问：

1. 哪类人在什么触发场景下重复使用？
2. 使用频率是否来自真实问题，还是提醒、积分、补贴或默认设置？
3. 哪个结果指标随使用发生变化？
4. 流失用户回到了什么替代办法？为什么？
5. 如果产品明天消失，哪些用户必须立刻找替代？
6. 用户是否愿意导入数据、邀请同事或改变工作流？

## 付费期

优先追问：

1. 谁付款、谁使用、谁受益、谁审批？分别记录。
2. 第一笔付款发生在什么条件下？是否包含人情、折扣或补贴？
3. 付款后，目标结果是否真实改善？
4. 是否续费、复购、扩席或增加使用量？
5. 没有续费的人回到了什么办法？
6. 重复付款购买的是产品结果、服务陪伴、合规要求还是其他价值？

一次付款证明一次选择，不证明持续需求。

## 现场观察记录

观察真实任务时记录：

- 触发任务的前一件事；
- 使用的所有外部工具和资料；
- 停顿、重复确认、复制粘贴、求助和放弃；
- 研究者没有帮助时能否完成；
- 用户意外使用的功能或绕开的设计；
- 任务完成后的实际结果；
- 下一次相同任务出现时采用的办法。

先记录看见的动作，再记录用户解释，最后记录诊断者推断。三者不得混写。

## B2B 角色拆分

企业产品至少检查四个角色：

| 角色 | 要确认什么 |
|---|---|
| 使用者 | 任务是否更容易完成，是否愿意改变流程 |
| 受益者 | 哪个结果改善，是否能被组织看见 |
| 付款者 | 预算换来了什么可量化效用 |
| 审批／阻止者 | 合规、安全、权限或组织利益是否阻断采用 |

角色分离时，任何一个关键角色的强阻力都可能让方案无法进入真实场景。
