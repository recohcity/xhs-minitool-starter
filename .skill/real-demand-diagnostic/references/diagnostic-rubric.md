# 真需求诊断判据

## 使用顺序

1. 先写原始事实与出处。
2. 再应用否决条件。
3. 最后评分并确定当前结论。

任何否决条件都优先于总分。不得通过给其他项目加高分绕过关键证据缺失。

## 需求真实性：0–12 分

| 字段 | 0 分 | 1 分 | 2 分 | 3 分 |
|---|---|---|---|---|
| `specific_person_scene` | 只有宽泛人群或假想用户 | 有较具体的人群与场景假设 | 有真实的人及近期实际事件 | — |
| `progress_consequence` | 只说想要某产品或“提升效率” | 想完成的变化较清楚 | 结果和不解决的后果可观察 | — |
| `workaround_cost` | 没有行动，也没有已知代价 | 偶尔抱怨、搜索或轻度绕路 | 重复绕路，并能说明时间、金钱、精力或机会成本 | 多人反复承担同类可核对代价 |
| `recurrence` | 纯假设 | 有一次真实发生 | 同一人多次或多人出现 | 同时跨人、跨时间重复 |
| `urgency` | “以后也许需要” | 有明确触发时刻 | 有截止期、风险或不行动的明显后果 | — |

强度解释：

- 0–4：弱。大概率仍在描述想法。
- 5–8：中。形成需求候选，但不宜扩大投入。
- 9–12：强。问题侧证据较强，仍需单独验证方案。

## 方案有效性：0–12 分

| 字段 | 0 分 | 1 分 | 2 分 | 3 分 |
|---|---|---|---|---|
| `mechanism` | 只有功能清单 | 能说出可能产生变化的机制 | 机制与目标结果有清楚因果链 | — |
| `unassisted_use` | 没有真实使用或全程演示 | 用户使用过，但需要持续帮助 | 用户可独立完成关键任务 | — |
| `observed_outcome` | 没有结果证据 | 只有主观好评或代理指标 | 观察到可感知变化 | 多次观察到目标结果，且有基线或对照 |
| `beats_status_quo` | 现有办法明显更顺手／便宜／可靠 | 各有取舍，优势只在部分条件成立 | 在关键选择标准上稳定胜过现状 | — |
| `repeat_choice` | 尚未再次遇到或再次使用 | 只有首次使用／新鲜感 | 同一人在相同场景再次选择 | 跨周期持续选择，或多人重复使用／推荐 |

强度解释：

- 想法期：写“未测”，不要把 0 分解释成产品失败。
- 0–4：弱。产品尚未证明能解决问题。
- 5–8：中。部分有效，关键链路仍有断点。
- 9–12：强。当前窄场景内的方案证据较强。

## 行为承诺等级

只按已经发生并可说明出处的最强行为标记：

| 等级 | 行为 |
|---|---|
| E0 | 口头喜欢、问卷意愿、点赞、候补名单、注册 |
| E1 | 围绕同一问题重复求助 |
| E2 | 自制替代或雇人处理 |
| E3 | 预约、试用、填写资料、学习、排队 |
| E4 | 导入数据、改变流程、邀请同事、放弃旧方案 |
| E5 | 定金、预购或正常条件付款 |
| E6 | 新鲜感过去后持续使用、续费、复购或主动推荐 |

另设 `payment_evidence`：

- 0：未测试付费。
- 1：低价尝鲜、人情单、补贴单或付款条件不清。
- 2：一次正常条件付款。
- 3：重复付费、续费或复购。

E6 可以出现在免费产品中，因此不能用 E6 替代付费证据。

## 否决条件

按顺序检查：

1. 没有一个真实的人与近期事件：最高只能判“证据不足”。
2. 只有 E0，且找不到绕路与代价：最高只能判“需求过弱／疑似伪需求”。
3. 没有无辅助真实使用：最高只能判“真需求候选，方案未证”。
4. 结果没有发生可观察变化：不能判方案有效。
5. 当前替代办法在关键标准上更好：当前场景不成立，不能靠其他分数补救。
6. 只有首次使用或一次付款：不能判重复需求已验证。
7. 只有单个用户：不能外推市场规模。

## 结论映射

| 结论 | 典型证据状态 | 建设决策 |
|---|---|---|
| 证据不足 | 用户与场景仍是假设 | 暂停增加功能，先观察真实事件 |
| 需求过弱／疑似伪需求 | 有兴趣，无绕路、代价和承诺 | 停止当前假设，重找场景 |
| 真需求候选，方案未证 | 问题侧有证据，产品尚未被独立使用 | 手工或原型测试最窄交付 |
| 需求存在，当前方案未解决 | 有真实问题，结果没改善或现状更好 | 改机制或换场景，不堆功能 |
| 方案有效，重复选择未证 | 首次结果改善，复用和承诺不足 | 测下一次真实触发 |
| 强场景初步成立 | 需求与方案证据较强，有迁移或重复行为 | 继续深挖同一窄场景 |
| 重复需求已验证 | 跨周期持续选择，需求与方案均有强证据 | 再验证获客、价格与单位经济 |

## 评分器输入格式

```json
{
  "product": "产品名称",
  "stage": "idea",
  "demand": {
    "specific_person_scene": 0,
    "progress_consequence": 0,
    "workaround_cost": 0,
    "recurrence": 0,
    "urgency": 0
  },
  "solution": {
    "mechanism": 0,
    "unassisted_use": 0,
    "observed_outcome": 0,
    "beats_status_quo": 0,
    "repeat_choice": 0
  },
  "commitment_level": 0,
  "payment_evidence": 0
}
```

`stage` 只允许 `idea`、`prototype`、`users`、`paying`。想法期仍保留方案字段并全部填 0，输出会把方案标记为“未测”。
